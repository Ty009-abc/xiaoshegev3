Turnaround OS V6 — Mission Engine

基于规则引擎的翻身任务计划生成器。消费上游身份画像、战略判决、命运推演，输出可分阶段执行的完整行动方案。

输入源

3

任务阶段

7d / 30d / 90d

测试覆盖

26 pass

1. Mission Engine API

generateMissionPlan(params)

消费 profile + strategy + projection，生成完整的三阶段任务计划。

const { generateMissionPlan } = require('core/turnaround-os')

const plan = generateMissionPlan({
  profile,    // ← identityEngine.buildIdentity() 输出
  strategy,   // ← turnaroundEngine.generateStrategy() 输出
  projection  // ← destinyProjectionEngine.projectDestiny() 输出
})

输入字段

字段来源引擎用途
profileidentityEngineV6财富阶段、安全月数、能力评估、时间预算、心理画像
strategyturnaroundEngineV6战略标题、主杠杆、错误游戏类型、成功条件、禁止事项
projectiondestinyProjectionEngineV6决策节点、双路径对比、限制因素、推演假设

输出结构

字段类型说明
versionstring固定 "6.0"
missionThemeobject任务主题：标题、战略目标、主杠杆、当前阶段、错误游戏
day7 / day30 / day90object三个阶段的计划，各含 missions[]、checkpoint、exitCriteria、failureResponse
planPrinciplesarray计划执行原则（含约束原则 + 通用原则）
weeklyRhythmobject周节奏：执行日、复盘日、最小/最大周时、聚焦/停止规则
strategicMetricsarray核心指标：安全月数、执行率、假设验证进度等
dependenciesobject任务依赖图谱：图、阻塞列表、关键路径、警告
rejectedMissionsarray被禁止的任务类型及拒绝原因
confidencenumber计划整体置信度 0-100
evidenceobject证据链：命中的规则、来源字段、战略链接、推演链接

scoreMissionPriority(params) — 辅助函数

const result = scoreMissionPriority({
  mission,     // 待评分的单条 Mission
  profile,     // 用户画像
  strategy,    // 战略判决
  projection   // 命运推演
})

// result: { priorityScore: 0-100, scoreBreakdown: {...}, ruleHits: [...] }

十维度评分：安全重要性(20%) → 战略重要性(18%) → 验证速度(12%) → 可逆性(10%) → 成本适配(10%) → 时间适配(8%) → 依赖就绪(6%) → 杠杆匹配(8%) → 推演影响(4%) → 用户能力匹配(4%)

2. 真实 Demo

用户画像：仓库管理员，月入5000、支出4800、安全月数仅0.6个月、每周可支配5小时、高焦虑(80)。

输入 → 输出 链路

SURVIVAL SINGLE_INCOME AI_PRODUCTIVITY → 战略标题: 第一步不是翻身，是活得更稳

World A (维持现状) → 三年后方向"下降"。World B (执行翻身) → 三年后方向"改善"。 决策节点：第一次行动 → 现金流安全边界 → AI工具上手 → 90天战略复查

生成的任务计划

1
建立现金流安全垫 Day 7

盘点7天非必要支出，砍掉至少20%。记录每笔支出并归类。目标是安全月数 +0.5 个月。

60分钟 零成本 p=87
2
时间结构审计 Day 7

记录7天时间去向，找出至少3个可优化时间段。当前可支配时间仅5h/wk。

30分钟 零成本 p=78
3
技能资产盘点 Day 7

列出所有技能(工作+业余+隐藏)，评估可变现路径。

45分钟 零成本 p=75
4
AI 工作流上线 Day 30

选择最重复的任务，用AI覆盖50%以上。记录时间对比。AI是生存期最低成本的效率放大器。

120分钟 低成本 p=69
5
价值主张提炼 Day 30

回答三问：帮谁、解决什么、独特在哪。浓缩成一句话价值主张。

60分钟 零成本 p=73
6
90天战略复盘 Day 90

回顾90天执行结果：验证/推翻的假设、基于数据决定下一步方向。

120分钟 零成本 p=71
7
可复制资产盘点 Day 90

梳理90天积累的所有可复用资产，制定系统化管理计划。

90分钟 零成本 p=71
8
第二收入验证 Day 90

选已验证的方向，尝试建立持续第二收入。目标不是金额，是证明"可以"。

180分钟 低成本 p=69

3. Mission 数据结构

每条 Mission 是一个冻结的契约对象，可追踪、可验证、有失败回退。

字段说明示例
missionId确定性 ID：MSN_D{phase}_{cat4}_{seq}MSN_D7_SAFE_01
phase阶段DAY_7 / DAY_30 / DAY_90
category任务类别 (17种)SAFETY_REPAIR / AI_WORKFLOW
title任务标题建立现金流安全垫
instruction具体执行指引盘点7天支出，砍掉至少20%
whyNow为什么现在必须做安全月数仅1个月，高脆弱
strategicPurpose战略目的先修复生存安全
validatesAssumption验证的假设削减支出可改善安全月数
linkedLeverage关联杠杆AI_PRODUCTIVITY
linkedWrongGame关联错误游戏SINGLE_INCOME
estimatedMinutes预计耗时 [1,1440]60
estimatedCostLevel成本NONE / LOW / MEDIUM
riskLevel风险LOW / MEDIUM / HIGH
difficulty难度EASY / MODERATE / HARD
priorityScore优先级分数 [0-100]87
proofOfCompletion完成证据要求["支出削减清单"]
successCriteria成功标准识别3项可削减支出
failureSignals失败信号无法找到可削减支出
fallbackAction失败回退转入第二收入验证

Mission ID 生成规则（确定性，同输入同输出）：

MSN_D{phase}_{category前4字母}_{2位序号}

例：DAY_7 + SAFETY_REPAIR + 01 → MSN_D7_SAFE_01
例：DAY_30 + AI_WORKFLOW + 01  → MSN_D30_AI_W_01
例：DAY_90 + REVIEW_AND_DECIDE + 01 → MSN_D90_REVI_01
